# Field Alignment

将两份数据结构的字段做三维比对，输出差异表格，并按用户需求生成对齐代码或 SQL。

---

## Step 1 — 解析输入

接受任意形式的数据结构描述：
- 数据库 DDL / SHOW CREATE TABLE
- JSON / JSON Schema
- 类定义（Python dataclass、PHP class、Java POJO、TypeScript interface）
- ClickHouse / MySQL 表结构
- 自然语言描述

若输入不完整，提示用户补充缺失的一侧。

---

## Step 2 — 输出三张对比表，请用户确认

### 相似或相同字段

| 表1 字段 | 表2 字段 | 类型是否一致 | 备注 |
|---------|---------|------------|------|
| id      | uid     | ❌ INT vs BIGINT | 描述 |

### 表1 独有字段

| 字段 | 类型 | 备注 |
|------|------|------|

### 表2 独有字段

| 字段 | 类型 | 备注 |
|------|------|------|

**输出后询问用户**：
> 表格是否准确？有无误判的相似字段或遗漏的对应关系？

---

## Step 3 — 确认对齐方向

用户确认表格后，询问：

1. **对齐方向**：把哪张表的字段对齐给哪张表？（以哪张为基准）
2. **对齐范围**：仅补充独有字段 / 还是同步类型差异 / 全量覆盖？
3. **参考代码**：是否有现有的 Model / Migration / INSERT 模板？（有则按其风格生成）

---

## Step 4 — 生成对齐产物

根据输入类型和对齐方向，生成对应产物：

| 场景 | 输出 |
|------|------|
| 数据库表 | ALTER TABLE / 新增字段 DDL |
| ORM Model | 补充属性定义（保持原有风格） |
| INSERT / SELECT | 补全字段列表，加 NULL 占位或默认值 |
| TypeScript | 补充 interface 字段 |
| 字段映射 | `源字段 → 目标字段` 映射表 + 转换代码片段 |

若字段类型不一致（如 INT vs BIGINT），标注并询问用户采用哪侧类型。
