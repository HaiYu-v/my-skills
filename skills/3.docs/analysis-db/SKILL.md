# DB Schema Audit

分析项目代码，产出每个数据库/每张表的状态报告。

---

## 输出格式（每张表）

| 字段 | 说明 | 取值 |
|------|------|------|
| 表名 | 原始表名 | — |
| 备注 | ddl的comment后的内容 | — |
| 介绍 | 一句话介绍表的用途 | — |
| 状态 | 使用 / 弃用 / 不清楚 | 判断依据见下方 |
| 表类型 | 可多选 | 底层表 / 业务表 / 爬虫结果表 / 中间临时表 |
| 涉及主要文件 | 最相关的 1 个文件路径 | — |
| 涉及主要界面 | 最相关的 1 个页面/路由 | — |
| 涉及主要项目 | 最相关的 1 个子项目/模块 | — |
---



## 分析步骤

### 1. 收集表清单

使用下面的sql, 获取某个库下的所有表的name和comment

数据库名称如果不知道, 请向用户询问

```bash
SELECT
    TABLE_NAME,
    TABLE_COMMENT
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = '{数据库}'
ORDER BY TABLE_NAME;
```

### 2. 判断表状态

- **使用**：近期代码中有 SELECT/INSERT/UPDATE/DELETE，或 ORM 模型被 Service 引用
- **弃用**：仅有建表 SQL，无任何业务代码引用；或文件名含 `old`/`bak`/`deprecated`
- **不清楚**：有模型定义但引用极少，或仅在注释中提及

```bash
# 搜索表名在代码中的引用（替换 TABLE_NAME）
grep -rn "TABLE_NAME" --include="*.java" --include="*.php" --include="*.py" --include="*.vue" --include="*.xml" . | grep -v "\.sql:" | wc -l
```

### 3. 推断表类型


|类型|名称|定义|典型特征|示例|
|---|---|---|---|---|
|**数据表**|原始数据表|从外部 API、第三方系统或数据推送接口获取的原始数据，保留原始结构，不做业务加工|字段贴近原始接口、更新频率由同步周期决定、一般不删除|TikTok Shop 订单同步表、平台 KOL 数据接口表|
|**爬虫表**|爬取数据表|爬虫程序采集的原始数据，通常结构较粗糙，存在噪声和冗余|含抓取时间戳、来源 URL、原始 HTML/JSON 字段、可能有重复数据|达人主页爬取表、商品评论爬取表|
|**临时表**|临时中间表|数据处理流程中产生的过渡性表，用于暂存中间结果、ETL 流转或业务处理的中间状态|生命周期短、可重建、不作为最终数据来源、通常带日期或版本后缀|固化脚本中间聚合表、分批处理缓冲表|
|**备份表**|数据备份表|对重要数据在特定时间点的完整或增量备份，用于灾难恢复、历史追溯或操作回滚|结构与源表一致、含备份时间戳、只读、按日期/版本命名|达人信息每日备份表、活动数据归档表|
|**任务表**|任务调度表|控制脚本、爬虫、ETL 流程等异步任务的调度与状态管理，记录任务执行的元信息|含状态字段（待执行/执行中/成功/失败）、重试次数、执行时间、优先级|爬虫任务队列表、数据固化调度表|
|**底层表**|固化数据表|脚本将原始数据/临时数据清洗、聚合、计算后固化的结构化结果表，是上层业务的数据基础|字段经过标准化、有明确的更新周期、数据可信度高、不直接对接用户请求|达人日维度指标表、商品销售聚合表|
|**实体表**|实体信息表|记录某类核心业务实体完整生命周期信息的主表，是系统中该实体的唯一权威数据源|含唯一标识、完整属性字段、创建/更新时间、状态字段、软删除标记|达人信息表、品牌表、商品表、用户表|
|**映射表**|关系映射表|记录两个或多个实体之间关联关系的表，通常无业务逻辑，只描述"谁关联了谁"|主要由外键构成、结构简单、数据量可能很大、支持多对多关系|达人-活动关联表、达人-商品绑定表、用户-角色映射表|
|**业务表**|业务流程表|直接支撑业务功能运转的表，记录业务行为、流程状态和操作数据，与用户操作强相关|含业务状态机字段、关联操作人/操作时间、有明确的 CRUD 操作、贴近产品功能|外联记录表、合作邀约表、消息会话表、活动报名表|
|**日志表**|操作日志表|记录系统操作、接口调用、数据变更、错误异常等审计流水，用于问题排查与行为追溯|只追加不修改、数据量大、含时间戳和操作主体、通常按时间分区或分表|API 调用日志表、用户操作日志表、数据变更流水表|
|**配置表**|系统配置表|存储系统参数、枚举值、业务规则、开关等全局配置，变更频率低但影响范围广|键值或结构化存储、变更需审计、通常有版本或生效时间、读多写极少|平台参数配置表、佣金规则表、枚举字典表|


### 4. 定位关联文件/界面/项目

```bash
# 找引用最多的文件
grep -rln "TABLE_NAME" --include="*.java" --include="*.php" --include="*.py" . | head -5

# 找前端路由/页面
grep -rn "TABLE_NAME\|api_endpoint" --include="*.vue" --include="*.ts" src/ | head -5
```
- **涉及主要文件**：引用次数最多的那个文件（Service/Mapper/Model 优先）
- **涉及主要界面**：最相关的 Vue 页面或路由路径
- **涉及主要项目**：所属子模块（如 `kol_outreach`、`collab_lab_script`、`admin`）

---

### 5. 对不清楚的表再处理
得到第一版的解析表格后, 对其中不清楚的表再处理, 看看能不能找到表的用处

再处理完后, 给出第二版的解析表格

> 注意: 要给出所有表的完整表格

## 注意事项
- 如果数据库较多（>3个），先列出库名让用户确认分析范围
- 表状态为不清楚时, 就不推算后面的表类型, 主要文件, 主要界面等
- 最终以 Markdown 表格输出，一个数据库一个表格, 便于复制到文档
- 主要文件和主要项目 不需要显示文件的完整路径，只显示文件名
- 如果表没有备注, 请自行推断, 格式为`(推断) xxx`
