# Check Skill Creator

为已有的 skill 创建配套的检查 skill，用于验证执行结果是否符合该 skill 的处理要求。

## 流程

### 第一步：定位被检查的 skill

1. 确认用户指定的 skill 路径或名称
2. 读取该 skill 的 `SKILL.md`，理解：
   - 该 skill 的**目标**：它要完成什么任务？
   - **输入**：接受什么类型的输入？
   - **输出**：产出什么文件/结果？格式是什么？
   - **关键处理步骤**：有哪些必须执行的步骤？
   - **质量要求**：有无明确的成功标准？

### 第二步：提取可检查的核心点

根据 SKILL.md 的内容，梳理出可验证的检查项，分类如下：

| 类型 | 示例 |
|------|------|
| **文件存在性** | 输出文件是否生成？路径是否正确？ |
| **格式正确性** | 文件格式是否符合要求（如 .docx、.xlsx）？ |
| **内容完整性** | 必要章节/字段是否存在？ |
| **命名规范** | 文件名是否符合 skill 规定的命名规则？ |
| **处理步骤** | 关键步骤是否都被执行？ |
| **边界条件** | skill 中提到的特殊情况是否被正确处理？ |

### 第三步：生成 check skill

**位置**：与被检查 skill 的 `SKILL.md`所在目录的同级目录
**命名**：`{skill-name}-check/SKILL.md`

生成的 check skill 结构如下：

```
{skill-name}-check/
└── SKILL.md
```

check skill 内容模板：

```markdown
---
name: {skill-name}-check
description: 检查 {skill-name} skill 的执行结果是否符合预期。当用户说"检查结果"、"验证输出"、"check 一下"、"执行检查"时，且上下文涉及 {skill-name} 的输出时触发。
---

# {Skill-Name} 执行结果检查

验证 {skill-name} skill 的输出是否满足所有要求。

## 检查项

逐项执行以下检查，记录每项的通过/失败状态：

### 1. {检查项名称}
- **检查内容**：{具体检查什么}
- **通过条件**：{明确的判断标准}
- **检查方式**：{bash 命令 / 读取文件 / 内容比对}

### 2. {检查项名称}
...

## 输出报告格式

检查完成后，以如下格式汇报结果：

✅ 通过 / ❌ 失败 / ⚠️ 警告

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 文件生成 | ✅ | 输出文件存在于正确路径 |
| 格式正确 | ❌ | 期望 .docx，实际为 .pdf |
| ... | ... | ... |

**总结**：X 项通过，Y 项失败，Z 项警告。
{如有失败项，给出修复建议}
```

### 第四步：确认并输出

1. 将生成的 check skill 写入对应路径
2. 向用户展示检查项列表，确认是否覆盖所有关键点
3. 如用户有补充，修改 check skill 后再保存

### 第五步: 失败处理
在skill的结尾加上
```
如果失败, 则重新执行{skill-name}(最多重复三次)
```

## 注意事项

- **检查项要具体可执行**，避免模糊描述（如"内容是否正确"应改为"是否包含 H1 标题"）
- **优先覆盖 skill 中明确规定的要求**，其次补充常识性检查
- **检查方式尽量自动化**：能用 bash 验证的不要靠人工判断
- 如果被检查的 skill 有多种输出模式，check skill 应分别覆盖每种模式
